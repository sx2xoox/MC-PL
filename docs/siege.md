# 초능력 공성전 (Superpower Siege) — 설계 문서

초능력전쟁의 능력을 그대로 쓰는 **두 팀 공수전**. 팀 인원은 자유(1대1부터 8대8 이상까지, 인원이 다른 팀도 가능).
스트리머 단편 콘텐츠용으로 **3판 2선승제**, 한 판 약 25분. 이 문서가 규칙의 기준입니다.
모든 시간·점수·체력은 설정(`config.yml` → `games.siege.*`)으로 바꿀 수 있습니다.

## 1. 전체 흐름

| 단계 | 시간(기본) | 내용 |
|---|---|---|
| 팀 구성 | — | 관리자가 `/게임 시작 공성전`. 참가자를 두 팀(A·B)으로 고르게 나눕니다(홀수면 한 명 차이). 혼자서도 시작할 수 있습니다(연습: 상대 팀은 비어 있고 봇도 없음, 점수·시간으로만 판이 끝남). |
| 판 준비 | 20초 | 판마다 능력을 새로 **무작위 배정**(아래 4절). 웅크리고 능력 아이템 우클릭(또는 `/게임 공성전 리롤`)으로 리롤 1번. 무적. |
| 전반 | 12분 | A팀 공격, B팀 수비. 마지막 3분은 **총공세**. |
| 하프타임 | 30초 | 공수 교대, 체력·쿨타임·게이지 초기화, 킷 다시 지급, 타워 복구. 능력은 그대로. |
| 후반 준비 | 5초 | 무적. |
| 후반 | 12분 | B팀 공격, A팀 수비. 마지막 3분은 **총공세**. |
| 판 종료 | — | 전반+후반 합계 **100점을 먼저** 낸 팀이 즉시 판 승리. 후반이 끝날 때까지 아무도 100점이 안 되면 점수가 높은 팀 → 동점이면 파괴한 타워가 많은 팀 → 처치가 많은 팀 → 그래도 같으면 **연장전 2분**(같은 공수로 계속, 먼저 점수를 낸 팀 승리, 아무도 못 내면 수비팀 승리). |
| 다음 판 | 쉬는 시간 1분 | 판 스코어를 먼저 2판 따낸 팀이 우승. |

## 2. 점수 (한 판 동안 전반+후반 합산)

| 일 | 점수 (기본) | 설정 |
|---|---|---|
| 적 처치 | +2 (처치한 팀) | `points.kill` |
| 도움: 처치 직전 8초 안에 그 적에게 피해를 준 다른 팀원 | 1명당 +1 | `points.assist`, `points.assist-seconds` |
| 현상금: 5연속 처치 중인 적을 처치 | +5 (처치 점수 대신) | `points.bounty`, `points.bounty-streak` |
| 성문 탑 / 중앙 탑 / 코어 파괴 | 공격팀 +15 / +20 / +30 (코어가 부서지면 그 반은 즉시 끝남) | `points.front-tower` 등 |
| 방어 성공: 지금 공격 가능한 타워가 4분 동안 버팀 | 수비팀 +5 (그 타워 최대 체력의 25% 회복, 다시 4분) | `points.defence*` |
| 총공세(각 반의 마지막 3분) | 타워 파괴 점수 ×1.5(반올림), 양 팀 부활 대기 −2초 | `climax.*` |

연속 처치는 죽으면 끝나고, 반이 바뀌면 처음부터 셉니다. 경기 결과의 MVP와 판 MVP는 점수 기여(처치·도움 점수, 가장 많이
때린 사람에게 타워 점수, 수비팀에 방어 성공 점수를 나눠서)가 가장 큰 사람입니다.

## 3. 타워

- 수비 진영에 **3개**: 성문 탑 → 중앙 탑 → 코어. **앞 타워가 부서져야** 다음 타워를 칠 수 있습니다(유리 보호막 연출,
  보호막 타워를 치면 "보호막" 안내).
- 타워 = 체력이 있는 수정(디스플레이 엔티티) + 보이지 않는 피격 판정. 공격팀의 **근접 공격과 능력 피해**만 체력을 깎습니다
  (능력에게 타워는 공격팀에게만 적이고, 보호막이 있는 타워는 적이 아닙니다). 수비팀은 자기 타워를 때릴 수 없습니다.
- 체력(공격팀 3명 기준): 성문 탑 1200, 중앙 탑 1500, 코어 1800. 실제 체력 = 설정 체력 × (`health-base-share` 0.25 +
  `health-per-attacker` 0.25 × 공격팀 인원). 1명이면 0.5배, 5명이면 1.5배, 8명이면 2.25배.
- 수비팀이 타워 반경 안에 있으면 그 타워가 받는 피해 감소(1명당 −20%, 최대 −40%).
- 10초 동안 피해를 받지 않고 공격팀이 반경 안에 없으면 초당 최대 체력의 1%씩 회복합니다.
- 공격받으면 수비팀에게 경고(소리·액션바, 3초마다), 체력 75·50·25%마다 전체 공지. 타워마다 보스바(체력·보호막).
- 파괴: 전체 타이틀, 폭죽, 무너지는 연출, 다음 타워 개방, 수비 부활 지점이 뒤로 물러납니다.
- 모양은 `game/siege/tower/TowerLook`으로만 그립니다. 기본은 `ModelTowerLook`(리소스팩 3D 모델, 팩이 없는 사람에게는
  같은 크기의 바닐라 블록 탑)이고, `SiegeGame#towerLook(TowerLook)`으로 바꿀 수 있습니다.

### 타워 모습

| 타워 | 모양 (약 3×3칸, 5~7칸 높이) |
|---|---|
| 전방 (성문 탑) | 네모난 성문 탑. 앞쪽에 쇠창살 성문과 팀 깃발, 지붕 위 화로에 수정이 떠 있음 |
| 중앙 | 팔각 탑. 위쪽 등불 방(기둥 4개 + 석판 지붕) 안에 수정이 떠 있음 |
| 코어 | 계단식 단 위에 오벨리스크 기둥 4개, 그 사이에 큰 수정이 떠 있음 |

- **손상 단계**: 체력 2/3 초과 = 멀쩡함, 1/3 초과 = 금 감, 그 이하 = 크게 부서짐(흉벽·지붕 일부 붕괴, 그을음, 돌무더기),
  파괴 = 폐허(밑동과 돌무더기만 남고 수정이 깨짐). 하프타임에 타워가 복구되면 다시 멀쩡한 모습.
- **팀 색**: 수정, 깃발, 빛나는 룬 틈이 수비 팀 색으로 칠해집니다.
- **보호막**: 앞 타워가 서 있는 동안 반투명한 계단식 돔이 타워를 감쌉니다.
- **피격**: 맞으면 잠깐 흰 테두리로 번쩍이고 흔들립니다. 수정은 천천히 돌며 위아래로 떠다닙니다.
- **리소스팩이 있는 플레이어**는 3D 모델(`ModelTowerLook`)을, **없는 플레이어**는 바닐라 블록으로 만든 같은 크기의 탑
  (석재 벽돌 → 금 간 벽돌 → 무너진 조약돌, 팀 색 유리 수정)을 봅니다. 팩을 받는 순간 플레이어마다 바뀌어 보이고,
  팩이 없는 사람에게 보라·검정 '텍스처 없음' 상자가 보이는 일은 없습니다.

## 4. 능력

- 판마다 **무작위 배정**: `games.siege.ability-pool`(능력 id 목록, 기본 경찰·광부·대장장이·총잡이·요리사)에서 뽑습니다.
  목록이 비어 있으면 `abilities.yml`에서 켜진 모든 능력.
- 같은 팀 안에서는 절대 겹치지 않고, 능력풀이 전체 인원보다 크면 두 팀 사이에서도 겹치지 않습니다(작으면 팀 사이에서만 겹침).
  능력풀이 한 팀 인원보다 작으면 켜진 다른 능력으로 채우고 관리자에게 알립니다. 없거나 꺼진 id는 건너뛰고 경고합니다.
- 리롤: 판 준비 시간에 1번(`rerolls`). 같은 팀이 가진 능력은 나오지 않고, 상대 팀이 안 가진 능력을 먼저 고릅니다.
- 한 판(전반·후반) 동안 같은 능력. 판이 바뀌면 새로 뽑습니다.
- 능력 아이템, 우클릭 액티브, F 궁극기, 게이지, 쿨타임, 궁극기 공지는 초능력전쟁과 같습니다(`games.superpower`의 킷, 게이지
  설정을 그대로 씀. 자기장 축소·보급 상자·밤낮은 없음).

## 5. 부활

- 죽으면 탈락하지 않고 **부활 대기** 후 자기 팀 부활 지점에서 다시 시작합니다. 대기 중에는 관전(가능하면 살아 있는 팀원 시점).
  능력·게이지·남은 쿨타임은 유지, 체력은 가득.
- 대기 시간: 기본 6초, 그 반에서 3번 죽을 때마다 +1초(최대 12초), 총공세 중 −2초.
- 부활 직후 3초 무적(공격하면 해제). 상대 팀 부활 지점 반경 6블록 안에 들어온 적은 1초마다 4 피해(스폰 킬 방지).
- 아이템은 떨어지지 않습니다. 킷은 반·판이 바뀔 때만 새로 지급.
- 부활 지점에는 맵의 자리(보통 3곳)를 차례로 쓰고, 인원이 더 많으면 옆으로 한 칸씩 비켜 섭니다.
- 경기 중 나간 사람은 돌아오지 못합니다. 한 팀이 모두 나가면 상대 팀이 우승합니다.

## 6. 맵: 협곡 요새 (`siege`)

- 한쪽 끝에 공격팀 부활 지점, 반대쪽으로 수비 진영과 타워 3개가 일렬. **길 3개**(가운데 큰길 + 좌우 우회로)가 타워마다
  모였다 갈라져 기습·우회가 가능. 높낮이·엄폐물·성벽.
- 맵과 게임은 `core/map/siege/SiegeSites`(부활 지점, 타워 위치·반경)로만 연결됩니다. id `siege`인 맵이 등록돼 있으면 그 맵을
  지은 월드에서 경기합니다. 기본으로 아래 **협곡 요새**가 등록되어 있으니 처음 한 번 `/게임 경기장 맵 siege`로 지어 두세요
  (안 지어져 있으면 시작할 때 안내가 나옵니다). 맵이 등록되지 않은 빌드나 테스트에서는 허브 경기장 중심에 일직선 임시 배치
  (`FallbackSiegeSites`, `SiegeGame#sitesOverride`)로 경기합니다.

높은 절벽(높이 약 20블록)에 둘러싸인 약 175×80블록의 협곡. 서쪽(-x)이 공격, 동쪽(+x)이 수비입니다. 관리자가
`/게임 경기장 맵 siege`로 한 번 지어 두면 됩니다. 좌표는 맵 중심 기준(x, z), 바닥 높이 64(서는 높이 65).

| 구역 | x | 내용 |
|---|---|---|
| 공격 진영 | -86 ~ -66 | 목책으로 둘러싼 야영지. 지붕 덮인 집결지에 **공격 부활 지점 8곳**(x -81/-78, z -6/-2/2/6). 앞쪽 문 3개(z 0, ±13). |
| 공성 들판 | -66 ~ -42 | 큰길(z ±3) + 북쪽 폐허 마을, 남쪽 채석장. 투석기·쓰러진 공성탑·충차·바리케이드가 약 10블록마다 엄폐물. |
| 강 협곡 | -42 ~ -28 | 깊이 6블록의 강. 큰길은 **돌다리**(z ±3), 북쪽은 **출렁다리**(z -28), 남쪽은 계단으로 내려가 **징검다리 여울**(z 26). 다리 옆 사다리로 빠져나올 수 있음. |
| 성벽 앞 | -28 ~ -15 | 말뚝 울타리, 부서진 충차, 바위, 포탄 구덩이. |
| 바깥 성벽 | -14 ~ -11 | 높이 8 + 성가퀴. 큰길은 **성문**(z ±3), 북쪽은 **무너진 틈**(z -26, 계단처럼 무너진 끝으로 성벽 위까지 오를 수 있음), 남쪽은 여울에서 이어지는 **지하 땅굴**이 성벽 아래로 지나 성 안 계단으로 나옴(x -9~-4, z 26). |
| 바깥 뜰 | -10 ~ 25 | **성문 탑**(x 2, z 0, 반경 6). 수비 부활 0: 탑 뒤 **위병소**(x 14~22, z 8~16, 서·북·동 문). 북쪽 무너진 막사, 남쪽 대장간·땅굴 출구. |
| 안쪽 성벽 | 26 ~ 29 | 큰길은 안쪽 성문, 북쪽은 **성벽 위 통로**(양쪽 계단, z -14~-30), 남쪽은 **쪽문**(z 19~20). |
| 안뜰 | 30 ~ 59 | **중앙 탑**(x 42, z 0, 반경 6). 수비 부활 1: 북쪽 **예배당**(x 44~53, z -32~-22, 남·동·서 문). 남쪽 과수원. 동쪽 끝에 고원으로 오르는 계단 3개(z 0, ±17). |
| 성채 고원 | 60 ~ 88 | 높이 69(5블록 위). 지붕 없는 정사각형 성채(x 61~87, z ±14) 한가운데 **코어**(x 74, z 0, 서는 높이 70, 반경 6). 문은 서(큰길)·북·남(우회로). 수비 부활 2: 코어 뒤(x 82/84, z ±1/±3). 안쪽 계단 2개로 성벽 위(높이 80)에 오를 수 있음. |

- 탑 발판은 반경 6 안에 바닥 말고는 아무 블록도 없습니다(위로 14칸). 발판 바깥 반경 8~9에 낮은 엄폐 벽.
- 부활 지점은 공격 8곳, 수비 단계마다 8곳(1대1~8대8). 공격 부활에서 코어까지 걸어서 약 160블록(30~40초).
- 큰길·북쪽·남쪽 길은 타워마다 반경 약 12 안에서 만나고 다시 갈라집니다. `SiegeMapTest`가 세 길 모두 각 타워에 닿는지,
  모든 땅이 양쪽 부활 지점에서 갈 수 있고 빠져나올 수 있는지, 절벽 위로 나갈 수 없는지 확인합니다.

## 7. 보는 재미

- 사이드바: `A팀 12 : 9 B팀 /100`, 판 스코어(●○), 판·전반/후반·남은 시간, 공격 팀, 공격 가능한 타워와 체력, 총공세 표시,
  내 능력, 내 킬/데스, 남은 리롤.
- 보스바: 판·반·남은 시간·공격 팀(총공세·연장전은 빨강), 타워마다 체력 보스바.
- 킬로그(능력 이름 포함), 처치·도움 점수 액션바, 현상금 공지, 타워 파괴 타이틀·폭죽, 방어 성공 공지, 총공세 타이틀·효과음,
  판 종료 타이틀과 판 MVP, 최종 결과(우승 팀, MVP).

## 8. 명령어

| 명령어 | 권한 | 설명 |
|---|---|---|
| `/게임 시작 공성전` | 관리자 | 공성전 시작 |
| `/게임 공성전` (`siege`) | 모두 | 도움말 |
| `/게임 공성전 점수` (`score`) | 모두 | 지금 점수와 판 스코어 |
| `/게임 공성전 리롤` (`reroll`) | 참가자 | 판 준비 시간에 능력 다시 뽑기 (웅크리고 능력 아이템 우클릭과 같음) |
| `/게임 리소스팩 [확인\|다시받기]` (`resourcepack`) | 모두 | 리소스팩 적용 확인(확인용 상자) / 다시 받기 (아래 11절) |
| `/게임 공성전 능력풀 [목록\|추가\|제거\|초기화] [능력]` (`pool list/add/remove/reset`) | 관리자 | 공성전에서 나오는 능력 관리 (능력 이름·id 자동 완성, 다음 판부터 적용) |

`/게임 설정`의 "공성전 진행"·"공성전 전투" 메뉴: 승리 판 수, 판 목표 점수, 전반·후반 길이, 하프타임, 판 사이 쉬는 시간,
리롤, 총공세 시간, 부활 대기, 공격팀 1명당 타워 체력. 나머지 값은 `config.yml`의 `games.siege`(한국어 주석)에 있습니다.

## 10. 구현 메모

- `game/siege/SiegeMatch`가 흐름(준비·반·하프타임·쉬는 시간·연장), 점수(`SiegeScore`), 타워(`tower/Tower`), 부활과 보호를
  맡고, 능력은 호스트 모드의 `SuperpowerMatch`(`runtime/MatchHost`)가 그대로 돌립니다: 바인딩, 입력, 쿨타임, 게이지,
  능력 컨텍스트와 정리. 타워의 피격 판정(보이지 않는 마네킹)은 `MatchHost#isExtraEnemy`로 공격팀에게만 적이 되어
  `AbilityContext#damage`·`enemiesNear`·`findTarget`이 닿습니다.
- 경기가 끝나면 타워 엔티티, 보스바, 능력이 만든 모든 것이 지워지고 참가자는 원래 상태로 돌아옵니다.

## 11. 리소스팩 (3D 타워 모델)

타워의 3D 모델은 플러그인 안에 든 **MCPL 서버 리소스팩**으로 보입니다(팩 형식 26.3 = 97). **기본으로 켜져 있고 따로 설정할
것이 없습니다**: 플러그인이 마인크래프트 접속 포트로 팩을 함께 내려주고(`/mcpl-pack/<해시>.zip`, 같은 포트로 팩을 내려주는 다른
플러그인과도 함께 쓸 수 있음), 접속하는 플레이어에게 그 사람이 접속할 때 입력한 주소로 팩을 보냅니다. 포트를 더 열거나 주소를
적을 필요가 없습니다. 팩을 받지 않아도 공성전은 그대로 할 수 있고, 그때는 바닐라 블록 모습을 봅니다. (이전 버전에서 만들어진
`config.yml` 은 적혀 있던 `enabled` 값을 그대로 쓰니, `false` 라면 `true` 로 바꾸세요.)

### 설정 (`config.yml` 의 `resource-pack`)

```yaml
resource-pack:
  enabled: true                 # 접속하는 플레이어에게 팩을 보냄 (거절해도 접속은 됨)
  mode: same-port               # same-port = 접속 포트로 함께 / separate-port = host-port 로 따로
  host-port: 8164               # separate-port 전용: 방화벽·공유기에서 이 TCP 포트를 열어야 함
  public-address: ''            # 비우면 플레이어가 접속한 주소. 그 주소로 이 서버에 닿지 않을 때만 (예: mc.example.com:25565)
  url: ''                       # 직접 올려 둔 주소를 쓰려면 여기에 (아래 참고)
  sha1: auto
  required: false               # true 면 팩을 거절한 플레이어는 접속할 수 없음
```

1. **접속 포트로 함께 (기본, `same-port`)**: 아무것도 하지 않아도 됩니다.
2. **따로 포트 (`separate-port`)**: 서버 앞에 Velocity·BungeeCord 같은 프록시나 TCPShield 같은 디도스 방어가 있으면
   마인크래프트 접속만 통과하므로 이쪽을 쓰고 `host-port` 포트를 열어 둡니다. 플레이어가 접속한 주소로 이 서버에 닿지 않으면
   `public-address` 에 이 서버의 도메인이나 공인 IP 를 적습니다.
3. **직접 호스팅**: `plugins/MCPL/MCPL-pack.zip` 을 GitHub 릴리스나 웹 호스팅에 올리고 그 직접 다운로드 주소를 `url` 에
   적습니다. 팩을 고쳐서 올렸다면 `sha1` 에 그 파일의 해시를 적거나 `''`(검사 안 함)로 둡니다.

### 적용 확인 (`/게임 리소스팩`)

- `/게임 리소스팩` (`확인`): 내 상태(적용됨 / 받는 중 / 거절 / 실패 / 안 보냄)와 받는 주소를 보여 주고, 눈앞에 **10초 동안**
  나에게만 보이는 확인용 상자를 띄웁니다. **초록 OK 상자**가 보이면 정상, 보라·검정 체크무늬나 아무것도 안 보이면 팩이
  적용되지 않은 것입니다. 관리자에게는 접속한 모두의 상태, 보내는 방식(접속 포트로 함께 / 별도 포트 / 직접 올린 주소)과 각자 받는
  주소도 나옵니다.
- `/게임 리소스팩 다시받기`: 팩을 다시 받습니다(거절했거나 받기에 실패했을 때). 관리자는 `다시받기 <플레이어|모두>`.
- `/게임 시작 공성전` 으로 카운트다운이 시작되면, 팩이 적용되지 않은 참가자를 관리자에게 한 줄로 알려 줍니다(클릭하면
  `/게임 리소스팩`). 시작을 막지는 않습니다(그 사람은 바닐라 블록 모습으로 봅니다).

`/게임 리로드` 로 바로 적용됩니다. 팩이 바뀌었으면(플러그인 업데이트) 접속 중인 모두에게 새 팩을 다시 보내고, 클라이언트에서는
같은 팩 자리를 새 팩이 대신합니다(쌓이지 않음). 받지 못한 플레이어(주소 오류, 거절)는 콘솔에 이유가 남고 바닐라 모습을 봅니다.

### 모델 만들기 (개발)

- 모델은 코드로 만듭니다: `tools/assetgen/models/towers.py` (STSV 의 assetgen 을 가져온 것: 공통 팔레트 공식, 32px 타일
  텍스처, 왼쪽 위 빛, 겹친 면·뚫린 상자 자동 검사). `python3 -I tools/assetgen/build.py` 가
  `src/main/resourcepack-src/models/*.bbmodel` 을 다시 씁니다(Blockbench 로 열어 손볼 수도 있음).
- `./gradlew build` 의 `resourcePack` 작업이 `core.pack.PackBuilder` 로 `.bbmodel` 을 마인크래프트 모델로 바꿔
  (`BBModelConverter`: 큐브, 회전, 발광, 틴트, 표시 설정) `assets/mcpl/models/item/`, 텍스처, 아이템 모델 정의
  `assets/mcpl/items/<id>.json`(틴트 면이 있으면 `minecraft:dye`)을 만들고 jar 에 넣습니다. 같은 소스는 항상 같은 해시.
  `src/main/resourcepack-src/assets/` 의 파일은 그대로 복사됩니다.
- 미리보기: `cd tools/assetgen/render && npm install` 후 `python3 -I tools/assetgen/build.py --render <폴더>`
  (Node + Playwright 로 단계별 시트를 PNG 로).
